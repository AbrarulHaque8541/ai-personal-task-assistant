# Android V1 design notes

The native Android project remains separate from the parent web prototype. It is a single-user Java Activity with Android platform APIs only. The task store is app-private encrypted file storage with no remote task service or third-party runtime dependency. The optional GitHub sideload updater is flavor-gated and has a narrow network permission scope; it does not upload task data.

**Later opt-in (not present and not a delivery promise).** A future engineering phase may evaluate Room/SQLCipher repositories and migrations, schedules, additional retained-backup or missing-key-recovery options beyond portable archive restore, model profiles, and transactional state. Model work is also deferred: safe user-initiated file import or approved remote sources, multi-source GGUF/ONNX/MLC model management, hash/format checks, signed catalogs, a pinned CPU inference engine, optional accelerators, and model lifecycle handling all need separate license, threat-model, device, performance, storage, and size qualification. Never activate partial or unverified artifacts. No model, language pack, or locale JSON is currently shipped or downloadable. Any future model/runtime/plugin/language pack must be fetched only after a deliberate user action, disclose source/license/exact size/device compatibility and storage impact before download, support progress/cancel/resume, hash/integrity checks, app-private storage, and complete removal of files and caches, and never download, update, index, or infer in the background. Do not claim model or locale capability without measured evidence and real-device testing. A future long user-initiated local-data import may use OS-compliant WorkManager or a user-visible foreground operation only if justified, bounded, cancellable, and tested; this does not authorize background model downloads, updates, indexing, or inference, or an always-on daemon.

Downloaded locale JSON is a later opt-in network feature, not part of the offline core; any such download must be user-triggered, show the exact size first, never auto-fetch, and be cancellable/resumable, verifiable, app-private, and removable with all caches. PRoot/Linux shell, ADB/Termux bridges, Accessibility/overlay access, persistent daemons, raw OS/system integration, an app CLI, executable plugins/hooks, cross-format/runtime hot-swapping, bounded automation, and AssistantProvider/cloud/Telegram integrations are deferred and unimplemented. Each requires separate security, compatibility, Android-policy, permission, licensing, and real-device tests before any claim, plus explicit user opt-in and least privilege. Do not expose mock controls or add arbitrary commands, secrets, raw database/model paths, or dynamic executable code.

Release engineering and hardware qualification remain later gates: pin and verify dependencies, decide the API/ABI matrix, produce an SBOM/license report, test migrations/security/lifecycle on physical devices, profile memory/thermal/battery, and verify signed reproducible release artifacts. **`<15 MB` is an unverified base release APK target only**; measure the exact byte count only after a genuine release APK is built. A pre-browser review recorded a 45,031-byte debug APK; that historical artifact predates later features and is not evidence for current `main`. CI has built debug variants, but no signed production APK is attached to the published `v1.0.0` release, and the release-size target remains unmeasured; essential UI/code/English strings have nonzero size.

**Unsupported/platform-limited.** PRoot is a user-space implementation of chroot-like behavior; it is not actual root/chroot privilege and cannot escape Android's app sandbox ([PRoot project](https://proot-me.github.io/), [Android app sandbox](https://source.android.com/docs/security/app-sandbox)). An ordinary APK cannot grant itself root, privileged/signature-level access, arbitrary system permissions, bypass user-mediated runtime/special-access decisions, or disable Android background limits. Special app access must go through Android Settings; runtime permission denial must leave core tasks usable. Android may stop background processes, so use only user-visible, OS-compliant work if a later feature justifies it—never claim an always-on daemon or bypass. GPU/NPU/MLC support is not universal and must be capability-detected; arbitrary downloaded executable code or self-updating plugins are not supported. Ship reviewed code through a signed APK/AAB or supported store delivery instead.

## Interaction architecture

**Simple path is the default.** It starts with “What do you want to get done?”, an everyday example, and an editable one-line task field. One-tap add uses no due date and medium priority, explained before the action. A second path opens the same editor with the text draft retained for date/priority choices. The task form supports Cancel/system Back.

**Power path is explicit, not imposed.** The top-bar path switch reveals search, date filters, and deterministic local Demo suggestions. It reads/writes the same `Task` list and store as Simple. The switch resets only transient search/filter state; it does not mutate task content. Both paths can edit, complete, and delete tasks. Deletion requires confirmation and has a seven-second Undo.

More settings expose appearance, app text size, a high-contrast palette, and actual boundaries for language, screen-reader, and reduced-motion support. TalkBack labels are set on controls; no separate TalkBack substitute is provided. UI strings remain English-only; dates use the device locale. The app has no custom looping animation or independent reduced-motion setting.

## Embedded browser

One composer has explicit **Task** and **Web** modes. A task draft is held only inside Daymark and restored when the user returns to Task; entering Web clears it from the shared field, and Web text is never routed to task creation. Web access starts **Offline**; an accessible Online checkbox is an explicit, locally persisted opt-in, with missing or malformed state defaulting to off. DuckDuckGo is the default, with Google, Bing, and Brave Search selectable. ChatGPT, Claude, Gemini, and Perplexity are plain HTTPS website shortcuts; there is no API integration, DOM automation, or claim that login or compatibility is guaranteed.


Bare domains and search providers use HTTPS. Explicit `http://` input is rejected by the address parser; main-frame HTTP links and HTTPS-to-HTTP redirect/downgrade attempts are blocked and shown as insecure/unsupported. The manifest retains `usesCleartextTraffic="false"` as a platform backstop. The Android [WebViewClient callback](https://developer.android.com/reference/android/webkit/WebViewClient) can inspect page/user/redirect navigations, and [`WebResourceRequest.isRedirect`](https://developer.android.com/reference/android/webkit/WebResourceRequest) reports server redirects; app-issued `loadUrl()` calls are separately validated by `BrowserAddress`. Any per-site HTTP exception needs a separate explicit request; no app-wide cleartext opt-in is part of this branch.

Safe Browsing defaults on; the browser-toolbar **Browser Settings** control persists the user's choice and applies it to current and future WebViews. Turning it off requires an explicit warning confirmation because it reduces protection against known harmful pages. The provider is platform-managed and not selectable; its Google/Play Services checks are separate from Online/Offline page-load policy, which does not promise zero platform traffic. HTTPS mixed content and file/content access are disabled; certificate errors are cancelled. JavaScript is enabled for ordinary web compatibility but no JavaScript-to-native bridge is exposed. Pop-up/new-window requests, downloads, and camera/microphone/location prompts are not supported. **Site history** lists at most 50 validated HTTPS origins (scheme, host, and non-default port) from app-private preferences (local, not encrypted). It never stores paths, queries, fragments, embedded URL credentials, or page titles; legacy entries are reduced to origins on launch and repeat visits to the same origin deduplicate. Selecting a site opens its origin, not its prior route; the current WebView continues to use the full validated URL. **Site history & data** clears the saved origins and current WebView history, its resource cache and SSL exception preferences, plus Web SQL/HTML5 Web Storage and cookies across all websites used in Daymark. Cookie deletion completes asynchronously. `WebView.clearFormData()` only dismisses a currently open autocomplete popup; it does not delete saved Android Autofill or password-manager data. The action cannot delete records held by sites/providers or browser data in other apps. See the official [WebView guide](https://developer.android.com/develop/ui/views/layout/webapps/webview), [Safe Browsing guidance](https://developer.android.com/develop/ui/views/layout/webapps/managing-webview), [WebSettings](https://developer.android.com/reference/android/webkit/WebSettings), [WebChromeClient](https://developer.android.com/reference/android/webkit/WebChromeClient), [WebStorage](https://developer.android.com/reference/android/webkit/WebStorage), and [CookieManager](https://developer.android.com/reference/android/webkit/CookieManager) references. Device-level network, redirect, permission, and UI checks remain pending.

Accessibility is a property of the app UI: keep controls usable through Android accessibility tools such as TalkBack. Do not request `AccessibilityService` as a generic permission/plugin shortcut. Android describes it for assistive technology; broad event monitoring can be resource-intensive. Defer any such service unless a concrete assistive use case justifies separate user opt-in, security review, and device tests ([Android AccessibilityService guidance](https://developer.android.com/guide/topics/ui/accessibility/service)).

## Local data and resource policy

`EncryptedTaskStore` serializes schema-versioned JSON, authenticates an AES-GCM format marker, and stores ciphertext in app-private internal files. A non-exportable AES key is held in Android Keystore; hardware backing depends on device support. I/O and cryptographic work run on a single foreground-owned executor. A shared validator checks every task, the 160-character title limit, and unique IDs before encoding and after decoding, so the writer cannot create a snapshot its own reader rejects. A truly absent store is a valid empty list; reads of an existing snapshot require its existing key, and malformed/schema/key/authentication/read failures remain distinct from empty data. The Activity shows an explicit unavailable state and does not clear task snapshots on load failure. Writes use Android `AtomicFile` with its commit/failure protocol, not a plain replacement fallback; the encrypted snapshot is read back and compared before save success. After a failed save, the attempted change stays visible as unsaved and editing pauses. These controls reduce some failure risks but do not establish a zero-data-loss guarantee. Automatic Android backup is disabled; user-triggered portable encrypted export/import is present in `main` and uses a generated 32-byte recovery key, not a passphrase. Corruption repair and recovery of a missing local Keystore key without a valid portable archive/key are not implemented.

The shared and Play merged manifests include normal `INTERNET`; only `githubSideload` additionally declares `ACCESS_NETWORK_STATE` for the gated updater. There is no runtime Internet prompt, scheduled job, foreground service, background polling, model process, or optional-content manager. Core task flows and encrypted app-private storage need no system permission. The updater publisher gate is disabled. If it is enabled in a future signed build, it checks GitHub only in foreground/manual use, asks the user to choose Wi-Fi-only (default) or allow mobile data before the separately consented APK download, then checks size/hash/package/version/minSdk/signer. A verified APK can be saved through the system document picker; Daymark does not launch Android's installer or request `REQUEST_INSTALL_PACKAGES`, and the user must open the saved APK manually. The production signer gate is closed, and this file/save/open path remains untested on device. Core task workflow is designed to work offline, but airplane-mode behavior requires a real device test. While open, the app necessarily performs UI/render and local I/O, so literal zero load is impossible; there is no app-owned background workload. CPU/battery near-zero claims require profiling and are not made here.

## Deferred roadmap

- **Voice:** no speech provider, microphone permission, or audio path exists. Future speech requires explicit permission at point-of-use, provider/audio disclosure, visible recording state, transcript review/edit, cancellation, and tests for denied permission, offline/provider failure, and no accidental task creation.
- **Models/assets:** no GGUF loader/download/inference, translation-pack install, or optional-content UI exists. Future downloads need deliberate tap, exact source/license/hash/size/device/storage disclosure, progress/cancel/resume, hash verification, removal of files and caches, no background download/index/inference, and unload after user-requested inference.
- **Power extensions:** no ADB/Termux bridge, PRoot setup, CLI, Accessibility/overlay service, persistent daemon, raw OS integration, plugin, cross-format/runtime hot-swap, dynamic code, or OTA/update path exists. Each needs separate security, compatibility, Android-policy, permission, and real-device tests, plus opt-in and least privilege.
- **Localization:** no language pack or locale JSON is shipped or downloadable; translations and right-to-left QA are incomplete. Any future locale fetch must be user-triggered and meet the download/removal policy above. Do not present non-English UI support as complete until all strings, formatting, layouts, accessibility labels, and user flows pass locale tests.

## Deferred optional integrations — future design only

No model provider adapters, provider router, or Telegram integration exist in the current source. The ideas below are optional future cloud/bridge designs only; the separate embedded browser opens ordinary websites but does not call model APIs or transfer task data. The local task workflow and no-download acceptance criteria continue to apply.

- **DeepSeek API:** DeepSeek Open Platform is a hosted LLM inference API, separate from the Harness names below. It needs a Bearer key, network, and token-based billing; rate limits can return HTTP 429. Privacy/retention/residency and credential revocation must be checked against current terms before any opt-in use ([API docs](https://api-docs.deepseek.com/), [pricing/limits](https://api-docs.deepseek.com/quick_start/pricing/), [terms](https://cdn.deepseek.com/policies/en-US/deepseek-open-platform-terms-of-service.html)).
- **Harness — exact target unresolved:** Do not assume the user's “Harness” means “DeepSeek Harness.” DeepSeek's preview-stage open-source desktop/web runtime is a design reference only, not an Android library; Harness API docs describe a DevOps platform, not generic LLM inference. Defer this item until its exact target and use case are identified ([DeepSeek Harness overview](https://www.deepseek.com/en/harness/), [repository](https://github.com/deepseek-ai/deepseek-harness), [Harness API docs](https://apidocs.harness.io/)).
- **Grok and Telegram:** The [Grok Bot announcement](https://x.ai/news/introducing-grok-bot) describes a separate hosted product announced for desktop and iOS, not a Telegram bot. The [xAI API overview](https://docs.x.ai/overview) describes a separate hosted model API. A custom [Telegram Bot API](https://core.telegram.org/bots/api) bridge would be a distinct, explicitly opted-in network service, requiring a hosted backend and protected bot token, with clear disconnect/revocation. Do not implement continuous phone polling: it conflicts with the offline/no-background-work goal.
- **Alibaba Cloud Model Studio:** This is a hosted API service for cloud Qwen and third-party models, not an on-device provider. It requires an Alibaba Cloud account and API key, region-specific network endpoints, and may incur per-token charges ([service overview](https://www.alibabacloud.com/help/en/model-studio/what-is-model-studio), [first Qwen API call](https://www.alibabacloud.com/help/en/model-studio/first-api-call-to-qwen)).

Provider-specific authentication, rate limits, retention, region routing, privacy, and pricing details must be rechecked against current official terms before implementation; see [ANDROID_SOURCES.md](ANDROID_SOURCES.md). Do not infer a provider's privacy, licensing, or cost terms from the separate Harness/Grok Bot/Telegram product names.

If providers are ever implemented, each adapter must sit behind one `AssistantProvider` contract that exposes capabilities, an offline/remote flag, configuration status, and an inference call. Route only to the provider the user explicitly selected; never silently fall back to cloud. Before each remote call, disclose exactly which task data leaves the phone, destination/region, network use, privacy implications, and possible cost. Send the minimum necessary context and never log prompts or keys. Encrypt user-supplied keys under Android Keystore when stored on-device; protect hosted-service tokens with server-side secret storage as appropriate. Never embed credentials in app source, APKs, or a public repository. Require explicit opt-in and provide revocation/disconnect controls. These safeguards are roadmap requirements, not current behavior or features. Telegram remains a separate hosted service requiring a backend and protected bot token; no polling runs on the phone.
