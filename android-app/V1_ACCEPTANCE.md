# Daymark Android V1 acceptance checklist

This is a release checklist, not a claim that every device-level item has already passed. Source-only status is distinguished from runtime verification.

## Attached brief: requirement status map

| Requirement area | Status | Evidence or gate |
|---|---|---|
| Offline task CRUD, dates/priorities, filters, actionable deterministic Demo suggestions, and one date/time or relative reminder per task | **Implemented in source** | JDK tests cover reminder policy, permission fallback, Doze limits, reboot/time-zone restoration, cancellation, snooze, and channel identity. Android UI/device behavior remains unrun. |
| Encrypted local task and reminder files | **Implemented in source** | Separate AES-GCM/Keystore app-private stores; task CRUD needs no permission. Reminder permission is requested when saved; no sync. Not Room/SQLCipher. |
| Embedded browser, selectable search engines, and AI-site shortcuts | **V1 implemented (source-level)** | Android System WebView is HTTPS-only and online-on-tap; cleartext is disabled, task drafts stay local, and AI sites are ordinary links. Device/network behavior remains unverified. |
| Room/SQLCipher, recurring schedules, profiles, migrations, export/recovery | **Later opt-in** | One-off timed reminders are implemented in source; recurring schedules and the other listed work are not. |
| GGUF/ONNX/MLC model manager, imports/catalogs, CPU runtime or accelerator | **Later opt-in** | No engine, model, importer, catalog, or model UI in V1; require provenance, license, parser, lifecycle, and device qualification. |
| Model/runtime/plugin/language packs and downloaded locale JSON | **Later opt-in** | No packages ship or download. Any future network fetch must be explicit, disclosed, cancellable/resumable, verifiable, removable with caches, and compatible with the offline core boundary. |
| Bounded user-requested local data work | **Later opt-in** | No worker exists in V1; any future WorkManager/foreground operation must follow Android constraints and remain cancellable, without scheduling model downloads, updates, indexing, or inference. |
| PRoot/Linux shell, app CLI, plugins/hooks, cloud and Telegram | **Later opt-in** | Absent; require separate threat models, narrow permissions/capabilities, explicit consent, security/licensing/performance tests. |
| Hardware benchmarks, API/ABI/device matrix, CI/SBOM/signing/reproducibility | **Later opt-in** | Not complete or measured; device-specific accelerators are not assumed. |
| Base release APK `<15 MB` | **Later opt-in** | Unverified release target only; measure exact bytes after a genuine release build, never use debug size, and make no claim before a release APK exists. The only existing debug artifact predates this browser and is stale; no APK was assembled for this branch. |
| Root/privileged/signature grants, background-limit bypass, permanent daemon, arbitrary downloaded executable code | **Unsupported/platform-limited** | Ordinary APKs cannot self-grant these powers or defeat Android lifecycle/policy restrictions. Use signed code delivery; never promise a resident daemon. |

“Later opt-in” means not present in this V1 and subject to a separately approved phase; it is not a commitment to ship. “V1 implemented” here is a source status, not proof of device-level acceptance.

## Permission UX (device/emulator required)

The manifest retains normal `INTERNET` for the browser and adds only reminder-specific `POST_NOTIFICATIONS`, `RECEIVE_BOOT_COMPLETED`, and `SCHEDULE_EXACT_ALARM`. Task CRUD remains permission-free. **More → Permission status** reports declarations and current notification/exact-access state without requesting anything. Notification permission is requested only when saving a reminder; denial means no reminder is created. Exact-alarm Settings are optional in the same flow; denial falls back to inexact timing. Device checks remain **unrun**; no API 36 tooling, Android build, or APK was used for this change.

- [ ] **Offline-by-default and persistence:** on a fresh install, confirm Online is off. Check it and verify the disclosure confirmation appears; choose **Stay offline** and confirm no page request or preference change. Then choose **Enable Online** and confirm the setting saves but makes no page request; each Go/site action does. Force-stop/relaunch and verify the explicit choice is remembered but no page is restored or loaded automatically. Corrupt/remove the preference and verify the state is Offline. Device/emulator test unrun.
- [ ] **Offline network gate:** with Online off, attempt Go, site shortcut and history selection; verify no Daymark page/resource request is sent. Turn Online off during a load and verify loading stops and the WebView is discarded. Return to Task mode and confirm no hidden page continues making requests. The disclosure must make clear that Android/Google Safe Browsing remains platform-managed and is not controlled by this switch. Device/emulator test unrun.
- [ ] **Safe Browsing provider and traffic:** verify the disclosure names Android System WebView Safe Browsing, Google/Play Services, possible threat-list updates and version-dependent URL-hash checks, and states that the Online switch does not control them or guarantee zero platform egress. Confirm the Safe Browsing provider is not selectable in Daymark while its on/off protection setting is available in Browser Settings. On representative Android/WebView versions, measure which checks/updates occur and when; verify the platform privacy-policy route. Device/emulator test unrun.
- [ ] **Browser/reminder permission boundary:** confirm `INTERNET` is used only by explicit WebView actions; reminder-specific permissions are `POST_NOTIFICATIONS`, `RECEIVE_BOOT_COMPLETED`, and `SCHEDULE_EXACT_ALARM`. Confirm no camera, microphone, location, storage/audio-read, wake-lock, or foreground-service permission.
- [ ] **Notification grant and denial:** create a reminder on API 33+. Grant notification permission and verify reminders are enabled; deny it and verify the reminder is not stored/scheduled, task flows remain usable, and no repeated pressure appears.
- [ ] **Repeated denial / “don't ask again”:** test the target Android version's persistent-denial behavior (including an explicit “don't ask again” choice when offered). Confirm the app does not rely on another prompt appearing, respects the choice, and offers the applicable Android Settings route; re-check access after returning.
- [ ] **Exact-alarm special access:** after saving a reminder without access, confirm the app schedules inexactly and explains possible delay before offering an opt-out and Android Settings page. Test grant and return without grant; verify the app re-checks `canScheduleExactAlarms()` and re-arms accordingly. Revoke access after creation and verify Android cancels the exact alarm while the separate inexact backstop remains eligible; it may be delayed. Verify no duplicate notification. Exact permission does not guarantee delivery at an exact time in Doze.
- [ ] **HTTPS-only and no downgrade:** type an explicit `http://` address and confirm it is rejected before navigation; from an HTTPS page, test an HTTP link and server redirect/downgrade, and confirm an insecure/unsupported message with no HTTP page opened. Verify `usesCleartextTraffic=false` remains in the merged manifest. Per-site HTTP exceptions require a separate explicit request.
- [ ] **Task operation under offline conditions:** with airplane mode on, verify task create/edit/search/filter/complete/delete/undo and local persistence remain available; confirm the task screen makes no browser request.

## Reminder acceptance (device/emulator required)

- [ ] **Date/time and relative timer:** create each type for a task; verify one reminder per task, local-only persistence, edits replace the prior alarm, and past/invalid dates and timer values are rejected.
- [ ] **Doze and inexact limits:** exercise a real device in Doze with exact access granted and denied. Confirm allow-while-idle scheduling is used, reminders may be delayed, alarms are subject to Android's per-app frequency limits, and no UI promises exact delivery.
- [ ] **Reboot, wall clock, and time zone:** schedule a date/time reminder and a relative timer, reboot, change time zone and wall clock, and verify persisted intent: local reminders remain at the selected local wall time in the new zone; timers retain their saved wall-clock deadline. Confirm no duplicate notification after restoration.
- [ ] **Cancellation and snooze:** cancel from the task UI and notification action; verify alarm and notification are removed. Snooze a delivered notification and verify a single 10-minute timer is scheduled and restored if rebooted.
- [ ] **Sound and notification channels:** choose default/custom/silent sounds in the system picker; verify each selection maps to the intended channel, existing channel settings are not rewritten when a sound is changed, and Android user channel controls remain authoritative.
- [ ] **Permission changes:** deny/revoke notification access and exact-alarm special access before and after scheduling; verify no reminder is falsely reported as exactly scheduled, the inexact backstop is not duplicated, and any delivery may be delayed. Re-open the app and confirm graceful re-check/degradation.

## User-flow acceptance (device/emulator required)

1. **Simple capture:** first screen asks “What do you want to get done?” and shows the school-trip example. Add a valid title with the keyboard action and button. Blank input is rejected; title can be edited before save. Quick add says it creates medium priority/no due date and shows the next step.
2. **Detailed capture/edit:** choose Add with a date or priority; verify the typed draft is prefilled, due date can be selected/cleared, and priority is Low/Medium/High. Cancel or system Back leaves the existing list unchanged. Edit a saved task and verify its ID/created time remain stable.
3. **Power path parity and suggestions:** switch to Power and verify exactly the same tasks and completion states are present. With search/non-All filters active, tap **Open** on a suggestion and separately activate one with keyboard Enter/Space/center; verify Daymark returns to All, clears search, scrolls to and focuses/highlights the matching task, and leaves its saved fields unchanged. If a displayed target has been deleted before activation, verify a safe message and refreshed suggestions with no task write. Add/edit in Power, switch back to Simple, and verify the same saved data remains visible.
4. **Complete/delete/cancel/undo:** complete and uncomplete a task. Delete shows a clear confirmation; Keep task cancels without changes. Confirm Delete, then Undo within seven seconds and verify task, due date, priority, and completion state return. Relaunch and verify the final state persists.
5. **Task/Web isolation:** type a task draft, switch to Web, and verify the visible field is cleared and no task text is sent. Enter a web query, press keyboard Search and the Go button, then return to Task; verify the original task draft is restored and the query was not added as a task.
6. **Search, Offline setting and tap-to-connect:** verify DuckDuckGo is the default and Google, Bing, and Brave Search are selectable. Confirm Online is off by default, checking it opens the disclosure confirmation, and only **Enable Online** saves the choice without making a page request. Each Go/site shortcut or history selection must be a separate tap. Verify the disclosure says providers receive the query/URL and ordinary connection data and may log it; pages may contact third parties; the Online switch gates Daymark page/resource loads but not platform-managed Android/Google WebView Safe Browsing; Safe Browsing may use version-dependent URL-hash-based checks (M126+ partial hashes via proxy, earlier local partial-hash lists with possible prefix-match server lookup), not that every full URL is sent; task text is never sent; and WebView diagnostic metrics are opted out. In **Browser Settings**, confirm Safe Browsing is on by default; turning it off presents a clear protection warning, persists only after confirmation, and changes the active/future WebView setting; re-enable it and verify the preference persists.
7. **HTTPS and downgrade policy:** confirm a bare domain resolves to HTTPS; explicit HTTP input is rejected. From a controlled HTTPS test page, confirm HTTP links and server redirect/downgrades are blocked with a clear message and no insecure page opens. Verify no global cleartext opt-in is present.
8. **AI website shortcuts:** tap each ordinary site shortcut and verify it opens only that provider's website; no API call, page automation, or task content is sent. Check login/render compatibility on-device; provider behavior is not guaranteed by Daymark.
9. **Site history and clear:** confirm the list is capped at 50 and stores only validated HTTPS origins (scheme, host, non-default port), never paths such as `/reset/<token>` or `/oauth/<code>`, queries, fragments, URL userinfo, or page titles. Verify legacy entries are reduced to origins at launch and visits with different routes/queries on the same origin deduplicate. Selecting an entry reopens that origin; the active current-page URL still retains its full route/query and is not changed by recording history. Use **Site history** and verify the confirmation accurately states that cookies and Web SQL/HTML5 Web Storage are cleared across all Daymark websites, cookie deletion is asynchronous, and saved Android Autofill/password-manager data is not cleared. Confirm the site list empties, current WebView history/cache/SSL preferences are cleared, and provider-held logs or other apps' browser data are not claimed to be deleted.
10. **Offline tasks:** enable airplane mode before first launch; create, edit, search/filter, complete, delete/undo, force-stop/relaunch, and verify the local task file. Confirm Task flows do not trigger Daymark browser page loads; platform-managed Safe Browsing behavior is separate from Task/Web mode.
11. **Keyboard, focus, and reduced motion:** operate capture, mode switch, search, dialogs, selection controls, buttons, and suggestion cards using keyboard/focus navigation; verify visible focus order and Enter/Space/center activation. Disable Android animations and verify suggestion navigation scrolls immediately while retaining the static focus/highlight cue. Verify Android Back/Cancel discards an unsaved edit and does not create a task.
12. **Text size and contrast:** check system font scaling and app Compact/Standard/Extra large. Check Standard and high-contrast palettes in light, dark, and system-following appearance. Confirm layouts scroll without clipped actions and text remains readable.
13. **TalkBack:** traverse every field/action with TalkBack. Confirm the task-specific completion, edit/delete, mode switch, search-clear, date/priority and storage-status labels are understandable and that dialogs announce their title/actions. Make the app itself accessible; do not ask for `AccessibilityService` as a generic permission/plugin workaround. Any future AccessibilityService needs a concrete assistive use case, separate opt-in/security review and device testing; broad event monitoring can be resource-intensive.
14. **Non-English locale:** test at least one non-English locale and an RTL locale. Dates/numbers currently follow device locale, but app strings remain English only; therefore **full non-English/RTL support is not accepted yet**. Translate every user-facing string and accessibility label, then repeat flows 1–13 before claiming support.
15. **Simple language and permissions:** review the task flow with nontechnical users. Open More → Permission status and confirm it reports `INTERNET` as browser-only, shows no runtime prompt, and leaves task flows usable. Verify the merged manifest declares no permission other than `android.permission.INTERNET`.

## Pack, localization, size, and background-work release gate

- [x] Current source has no pre-downloaded models/GGUF weights, language packs, locale JSON, compiled inference runtime/native model engine, plugin packs, demo task dataset, or model artifacts; no optional-content downloader exists. UI strings are English-only source resources/code, not a downloadable locale pack.
- [ ] After a genuine **release** APK build, inspect its contents and record the exact byte size of the base release artifact with `stat -c '%s bytes' <built-apk>`. The spec's **`<15 MB` is an unverified target**; a debug APK does not satisfy it. Record the exact byte count and artifact variant, and make no size claim before a release artifact exists.
- [ ] If any optional download is implemented, test that it starts only after an explicit user action and discloses source, license, exact size, device compatibility/performance impact, and storage impact before download. Verify cancellation, resume, hash/integrity checking, app-private storage, and complete removal of the asset and all caches. Current behavior is absent; these checks are **unrun/not applicable until a feature exists**.
- [ ] If localization is added, verify there is no automatic locale fetch; the user initiates it, sees its exact size before download, can cancel/resume, and can verify and remove locale data and caches. No locale JSON/language pack is currently shipped or downloadable; no additional locale capability is claimed.
- [ ] Before any model/locale capability or compatibility claim, measure the relevant asset/runtime footprint and performance and test on representative real devices. No model/runtime capability currently exists.
- [x] Source has no app-owned polling, scheduled work, foreground service, inference loop, or optional-content update path.
- [ ] Profile actual device idle/background behavior. Zero CPU load while the UI is open is impossible; state only measured near-zero idle/background results, never a literal zero-load guarantee. Android controls background execution; the app cannot disable platform limits.

## Explicitly deferred (not V1 functionality)

- Voice/push-to-talk: no microphone permission/provider/audio path is present. A future transcript must be shown and editable, then require explicit user confirmation before task creation.
- System permissions: V1 has no permission requirement or prompt. A future runtime permission must be requested only after the user starts the feature, with a clear purpose and graceful denial. Route special access through Android Settings; an ordinary APK cannot grant itself root, privileged/signature-level or arbitrary system permissions, or disable Android background limits. Do not claim root/superuser access.
- PRoot/Linux setup: absent. PRoot is user-space, chroot-like behavior; it is not actual root/chroot privilege or a way around Android's app sandbox or permission boundaries.
- ADB/Termux bridges, Accessibility/overlay access, persistent daemons, raw OS/system integration, arbitrary executable plugins, cross-format/runtime hot-swapping, GGUF/local model inference, CLI, hot reload, and app/OS OTA are deferred and unimplemented. Each requires separate security, compatibility, Android-policy, permission, and real-device tests before any claim; never recommend bypassing platform/security rules.
- No language packs or locale JSON are shipped or downloadable; UI strings are English-only. Localization and RTL layout remain release blockers for any non-English market.
- The Android Gradle debug build is verified, but APK install/launch, Keystore runtime behavior, airplane-mode runtime, TalkBack, device font scaling, and device profiling remain unverified because no device/emulator is available. The source-level contrast calculation passed but is not a rendered-UI test.

### Future AssistantProvider and Telegram policy

Any future local or remote provider must implement one `AssistantProvider` contract exposing capabilities, offline/remote status, configuration status, and an inference call. The user must explicitly select the provider, and routing must never silently fall back to cloud. Before a remote call, disclose what information leaves the phone and possible cost, send minimum context, never log prompts or keys, and encrypt user-supplied credentials with an Android Keystore-protected key. This contract, routing, and remote credential support are not in V1.

Telegram is a separate hosted-bot service that needs a backend and bot token. It conflicts with V1's offline/no-backend/no-background design and remains deferred; do not add a mock connection or background phone polling.
