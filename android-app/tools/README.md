Run `sh ./tools/run-core-tests.sh` from `android-app/`. It compiles the task logic, updater policy, restart-recovery record, strict release JSON parser, GitHub metadata client, and APK downloader with the local JDK only. Host fixtures drive fake HTTP connections through the production metadata, downloader, and verification core. A bounded repeat-byte stream proves the full production path accepts exactly 104,857,600 bytes and rejects an actual 104,857,601-byte body without a 100 MiB memory allocation. Other fixtures cover mid-transfer cancellation, simulated interruption/restart cleanup, retention of a digest-bound `.verified.apk` plus expected metadata in persistent no-backup app storage rather than Android's evictable cache, and restart revalidation of digest, package, and signer before any save offer. At most one APK (up to 100 MiB) can be retained until explicit discard; there is no expiry policy. The tests prove cleanup removes only `.partial` files. Policy tests also verify that hash/signer verification failures delete unverified temporary files. A minimal `Context` stub exists only under `tools/host-stubs` and is never included in Android app sources. The suite uses no Android SDK, Gradle, network access, APK assembly, or external libraries.
