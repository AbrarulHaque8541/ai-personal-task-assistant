Run `sh ./tools/run-core-tests.sh` from `android-app/`. It compiles task logic, updater policy, restart-recovery metadata, the pending picker transaction reference, SAF APK saver, strict release JSON parser, GitHub metadata client, and APK downloader with the local JDK only. Host fixtures drive fake HTTP connections through the production metadata client, downloader, verification, and digest-addressed promotion path. A bounded repeat-byte stream proves the production path accepts exactly 104,857,600 bytes and rejects an actual 104,857,601-byte body without a 100 MiB memory allocation.

Restart coverage records expected metadata before transfer, exercises production download → verification → promotion, then constructs a new recovery-store object, resolves the promoted artifact, and revalidates its persisted digest, package/version identity, minimum SDK, and signer expectations. It also confirms that modified promoted bytes fail revalidation. Simulated pre-verification process death proves startup cleanup removes only abandoned `.partial` staging files without touching user documents or task data; it does not fabricate a `.verified.apk`.

The picker-rotation regression serializes/restores the small `PendingSaveTransaction` snapshot before the simulated picker result and verifies its digest/version binding, UUID title, and reserved temporary-name recognition. A source check separately verifies that `MainActivity` writes/restores this reference through saved instance state, reloads release metadata and the verified APK from the existing app-private recovery record, and revalidates that source before handling the callback. No SAF URI or credential is stored in the saved transaction.

SAF fixtures invoke the same production saver used by Android through a **host fake provider**. Success coverage stages a unique `.tmp` picker title, copies the bytes, independently opens the destination for read-back, compares the destination bytes and SHA-256 with release expectations, and only then finalizes the name. Other fixtures simulate process death during transfer (the remaining content stays under `.daymark-incomplete-<token>`), an ordinary copy I/O failure (best-effort deletion is confined to the created document), a provider without rename support (no APK bytes are written), and a final-name collision (an unrelated document remains unchanged).

When a picker callback arrives without valid saved transaction state, Android source uses only the exact new URI returned by that `ACTION_CREATE_DOCUMENT` request: it best-effort renames the document to a unique orphan `.tmp` marker and then deletes that URI. It never searches for or deletes a document by display name, so unrelated documents are not targeted. If the provider rejects both rename and deletion, cleanup cannot be guaranteed; the default UUID temporary title or a successful orphan rename keeps any residue identifiable. If the app dies after receiving a result but before staging begins, the unique temporary title remains non-final-looking; after staging begins, the incomplete marker distinguishes partial content. The callback URI is deliberately not persisted, so the app cannot automatically resume a provider write after process death; the verified app-private source remains available for retry or explicit discard.

These fixtures establish host-code behavior only. They do **not** prove that Android's real document providers support rename, read-back, cleanup, finalization, or non-overwrite semantics consistently, nor that rename is atomic. A provider may reject an operation or behave differently; runtime behavior requires device testing. The suite uses no Android SDK, Gradle, network access, APK assembly, or external libraries. A minimal `Context` stub exists only under `tools/host-stubs` and is never included in Android app sources.
