Run `sh ./tools/run-core-tests.sh` from `android-app/`. It compiles the task logic, updater policy, restart-recovery record, SAF APK saver, strict release JSON parser, GitHub metadata client, and APK downloader with the local JDK only. Host fixtures drive fake HTTP connections through the production metadata client, downloader, verification, and digest-addressed promotion path. A bounded repeat-byte stream proves the production path accepts exactly 104,857,600 bytes and rejects an actual 104,857,601-byte body without a 100 MiB memory allocation.

Restart coverage records expected metadata before transfer, exercises real production download → verification → promotion, then constructs a new recovery-store object, resolves the promoted artifact, and revalidates its persisted digest, package/version identity, minimum SDK, and signer expectations. It also confirms that modified promoted bytes fail revalidation. Simulated pre-verification process death still proves startup cleanup removes only abandoned `.partial` staging files without touching user documents or task data; it no longer seeds a fake `.verified.apk`.

The SAF host fixtures invoke the same production saver used by Android. They simulate process death during a write and verify that any remaining partial document has a conspicuous `.daymark-incomplete-<token>` suffix rather than a final `.apk` name, that providers without rename support receive no APK bytes, and that a final-name collision leaves an unrelated document unchanged. Android document providers do not guarantee universally atomic rename/finalization behavior; failed finalization keeps the app-private verified source and best-effort leaves any provider-side copy clearly marked for inspection or cleanup.

At most one APK (up to 100 MiB) can be retained in app-private storage until explicit discard; there is no expiry policy. Policy tests also verify that hash/signer failures remove unverified temporary files. A minimal `Context` stub exists only under `tools/host-stubs` and is never included in Android app sources. The suite uses no Android SDK, Gradle, network access, APK assembly, or external libraries.
